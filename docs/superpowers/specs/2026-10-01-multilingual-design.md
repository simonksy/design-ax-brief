# Design AX Brief — 다국어화 (5개 언어) 설계

**작성일:** 2026-10-01
**상태:** 설계 승인(대화) → 스펙 리뷰 대기
**범위:** 콘텐츠·UI 다국어화. 글로벌 결제는 별도 후속 스펙(“범위 밖” 참고).

## 1. 목표와 성공 기준

전 세계 사용자가 사이트에서 자기 언어를 고르면 카드뉴스 요약(헤드라인·본문)과
전문(full)을 그 언어로 읽는다.

- **언어 풀:** English(`en`), 한국어(`ko`), 日本語(`ja`), 简体中文(`zh`), Español(`es`).
- **성공 기준**
  1. 매일 자동 발행분 40장이 5개 언어 모두로 발행되고, 언어별 검증을 통과하지 못한 칸만
     원문 언어 요약 + “번역 준비 중” 라벨로 대체된다.
  2. 언어 선택(자동 감지 + 수동 전환)이 홈·대형 카드·아카이브·공유 페이지에서 동작한다.
  3. 기존 공유 링크 `/s/{section}/{id}`가 깨지지 않는다(한국어로 열림).
  4. 테스트 단계에서 최근 노출분(약 6일 × 40장)을 백필하고, 안정화 뒤 전체 2,534장으로 확대한다.

## 2. 파이프라인

```
원문(언어 X) → ① 원문 언어 요약 → ② 사실 검증 → ③ 5개 언어로 번역 → ④ 언어별 검증 → ⑤ 언어별 빌드
```

수집·URL/스토리 중복 필터·큐레이션·미디어 단계는 지금과 같다(언어 무관).

1. **원문 언어 요약 (ax-writer 변경).** 작성 단계가 한국어 대신 원문 언어 X로 헤드라인
   (두 줄, `\n`)·한 줄 본문·전문 블록을 쓰고 `source_lang: X`를 기록한다(BCP-47 기본 코드).
   X가 풀 밖의 언어(예: 독일어)여도 X로 쓴다 — 이 요약은 번역의 원천일 뿐 사이트에 노출되지 않는다.
2. **사실 검증 (현행 enrichment 패스).** 원문을 다시 읽고 X 요약의 사실·수치·인용·고유명사를
   원문과 대조해 고친다. 같은 언어끼리 대조하므로 지금(영→한)보다 정확하다. 이후 모든 언어가
   이 확정본을 물려받는다.
3. **번역 (서브에이전트, API 크레딧 미사용).** `pipeline/translate.py jobs`가 카드 × 언어마다 완결된
   번역 지시문을 담은 작업 파일을 만들고, Claude Code 서브에이전트 `ax-translator`가 답 파일을 쓴다
   (X가 풀 안이면 X 버전은 요약 그대로). 규칙: 사실·수치·날짜·인용·고유명사 불변, 헤드라인 두 줄
   유지, 언어별 길이 한도(아래 표), 이미지·영상 블록은 그대로 두고 `cap`만 번역.
4. **언어별 검증 (`translate.py apply` 내장).** 각 번역을 X 요약과 대조:
   - 숫자 토큰 집합 일치(통화·퍼센트 포함), 라틴 문자 고유명사(대문자 시작 토큰·제품명) 보존,
     인용 블록 수 일치, 블록 구조(종류·순서) 일치, 헤드라인 `\n` 1개, 길이 한도.
   - `translate.py apply`가 답을 검증해 반영한다. 실패하면 오류 내용을 지시문에 넣은 재시도 작업
     파일을 만들고 에이전트가 다시 답한다(최대 2회) → 그래도 실패면 그 칸은 미번역 처리(§5).
   - 한국어 결과는 기존 humanize-korean 윤문을 거친다(사실 불변). 다른 언어는 번역 프롬프트에
     해당 언어의 번역투 금지 규칙을 포함한다.
5. **빌드 (`build_data.py`, `build_archive.py` 확장).** 언어별 산출물을 만든다(§4).

| 언어 | 헤드라인 줄당 | 본문 |
|---|---|---|
| ko / ja / zh | ≤ 14자 | 28–46자 한 문장 |
| en / es | ≤ 32자 | 70–120자 한 문장 |

(ko 값은 현행 규칙. ja/zh는 ko와 같은 시각 폭으로 시작하고 렌더 검증으로 조정. en/es 값은
현재 카드 폭 기준 추정치이며 구현 첫 단계에서 렌더로 확정한다.)

## 3. 사이트

### 언어 선택
- **첫 방문:** Worker가 `Accept-Language`에서 풀의 첫 일치 언어를 고른다. 없으면 `en`.
- **수동 전환:** 상단 언어 메뉴(EN · 한국어 · 日本語 · 中文 · ES). 선택은 쿠키 `ax_lang`(1년)에
  저장되고 자동 감지보다 우선한다.

### URL
- 언어별 경로: `/en/`, `/ko/`, `/ja/`, `/zh/`, `/es/` (홈), `/{lang}/large`, `/{lang}/archive`.
- `/` → 쿠키 > `Accept-Language` > `en` 순으로 정해 `/{lang}/`로 302.
- 모든 페이지에 `hreflang`(5개 + `x-default`=`/en/`) 링크.
- 공유: `/s/{lang}/{section}/{id}` — OG 제목·설명이 그 언어. 기존 `/s/{section}/{id}`는 그대로
  두고 한국어로 열린다(이미 퍼진 링크 보호).
- 정적 HTML은 하나로 두고 언어는 경로에서 읽는다(Worker가 `/{lang}/*`를 같은 앱 HTML로 서빙하며
  `<html lang>`과 데이터 스크립트 경로만 바꿔 넣는다).

### UI 문구
- `axbrief-app.jsx`·`axbrief-app-large.jsx`·`archive.html`의 하드코딩 한국어 문구를
  `i18n/{lang}.json` 사전으로 뺀다. 사전은 `translate.py --ui`로 한 번 번역하고 사람이 검토한다.
- 날짜·숫자는 `Intl.DateTimeFormat`/`Intl.NumberFormat`(언어 코드 기준).

### 미번역 카드 (백필 기간)
- 폴백은 카드 단위다: 어떤 화면이든 카드에 해당 언어가 없으면 원문 언어 요약(풀 밖 언어면
  `en`, 그것도 없으면 `ko`)을 보여주고 그 언어 UI로 “번역 준비 중” 라벨을 단다.
- 테스트 단계 백필 범위(최근 노출분)에서는 라벨이 보이지 않아야 한다 — 이것이 백필 완료 판정.

### 페이월·프리미엄
- 첫 카드 무료·나머지 잠금 로직은 그대로. 전문 API에 언어 인자 추가:
  `/api/premium/full?lang=en&section=…&id=…`. 해당 언어가 없으면 원문 언어 → 한국어 순 폴백,
  응답에 `lang`(실제 반환 언어) 포함.
- 지식 그래프 요약(`/api/insights/summary`, Claude Haiku)은 요청 언어로 생성, KV 캐시 키에 언어 포함.

## 4. 데이터 형식

### 카드
```json
{ "id": "…", "url": "…", "source": "…", "accent": "#…", "motif": "…", "image": "…",
  "source_lang": "en",
  "text": {
    "en": {"headline": "…\n…", "body": "…", "full": {"mode": "summary", "blocks": […]}},
    "ko": {…}, "ja": {…}, "zh": {…}, "es": {…},
    "_src": {"lang": "de", …}            // X가 풀 밖일 때만: 원문 언어 요약(비노출)
  },
  "i18n_status": {"ja": "fallback"}      // 검증 실패로 폴백된 언어만 기록
}
```
- 언어 무관 필드(URL·이미지·영상·색·모티프·출처명)는 단일.
- **하위 호환:** `text`가 없는 옛 카드는 최상위 `headline/body/full`을 `ko`로 읽는다.
  새 카드도 전환기 동안 최상위 필드에 `ko` 값을 함께 써서, 언어 분기 전 코드가 그대로 돈다.
- `roll.py`(덱 이동)·`update_ledger.py`·`story_dedup.py`·`build_archive.py`는 `text`를 보존한다.
  스토리 원장은 `source_lang` 요약을 우선 사용한다(영문 원제 비교 정확도 유지).

### 산출물
| 파일 | 내용 |
|---|---|
| `axbrief-data.{lang}.js` | 언어별 `window.AX_SECTIONS` (전문 제외 티저) |
| `axbrief-data.js` | 기존 경로 유지 = `ko` (구 링크·캐시 호환) |
| `premium/{lang}/{section}.json` | 언어·섹션별 전문 (Worker만 읽음, 정적 403 유지) |
| `archive-data.{lang}.js` | 언어별 아카이브 티저 |
| `s/{lang}/{section}/{id}.html` | 언어별 OG 공유 페이지 |
| `i18n/{lang}.json` | UI 사전 |

- **프리미엄 분할 이유:** 현재 단일 `premium/full.json`이 7.3MB이고 5개 언어 × 매일 증가하면
  Cloudflare 정적 파일 한도(25MB)에 닿는다. 언어·섹션별로 쪼개 Worker는 필요한 파일만 읽는다.
  기존 `premium/full.json`은 전환 기간 동안 `ko` 폴백용으로 유지하다 제거한다.
- 지식 그래프(`archive-graph.js`)의 노드·링크는 언어 무관(키워드는 `en` 기준으로 생성),
  라벨만 언어별 아카이브 데이터에서 붙인다.

## 5. 실패 처리

| 상황 | 처리 |
|---|---|
| 한 카드의 한 언어가 검증 실패(재시도 2회 후) | 그 칸만 원문 언어 요약(풀 밖 언어면 `en`, 그것도 없으면 `ko`) + 라벨, `i18n_status`에 기록. 나머지는 정상 발행 |
| 원문 언어 요약 없음 / 사실 검증 실패 | 그 카드 발행 안 함(현행과 같음) |
| 번역 단계 전체 실패(에이전트 실패·사용량 한도) | 원문 언어 + `ko`로 먼저 발행, 실행 로그에 누락 언어 기록. 다음 실행에서 `translate.py jobs --news`로 빠진 언어만 보충 |
| UI 사전에 키 누락 | `en` → `ko` 순 폴백, 빌드 시 누락 키 경고 |

## 6. 의존성·비용

- **API 크레딧 없음:** 번역은 매일 아침 자동 실행(`claude -p`, Claude 구독) 안에서 서브에이전트가 한다.
  API 키·API 호출이 없다(2026-10-01 사용자 결정). 비용은 구독 사용량으로 잡힌다.
- **러닝타임:** 일 40장 × 4개 언어 = 160작업. 섹션당 작업 파일 1개(20작업)·에이전트 1개 → 일일 실행
  +약 20~40분 예상.
- **전체 백필:** 2,534장 × 4 ≈ 10,000작업 — 한 세션에 무리이므로 묶음(예: 80작업)으로 나눠 여러 날에
  걸쳐 돌린다. 소규모 실행으로 통과율·소요 시간을 잰 뒤 일정을 정한다.
- **나중에 API로 전환:** 작업 파일·검증·데이터 형식이 호출 방식과 독립이라, 키를 넣고 호출 계층만
  추가하면 바꿀 수 있다.

## 7. 테스트

- **단위(파이썬):** 번역 검증기(숫자·고유명사·블록 구조·길이·줄바꿈 — 통과/실패 사례),
  `text` 맵 roll 보존, 옛 카드 폴백 빌드, 언어별 산출물 생성, 프리미엄 분할, 공유 페이지 경로.
  에이전트 답은 고정 답 파일 픽스처로 대체.
- **Worker(vitest):** `/` 리다이렉트(쿠키·헤더·기본값), `/{lang}/*` 서빙과 `<html lang>`,
  구 공유 링크, `/api/premium/full?lang=` 폴백·권한, insights 캐시 키 언어 분리.
- **렌더:** 헤드리스 Chrome으로 5개 언어 홈 스크린샷 + 데이터 구조 검증(카드 수, 라벨 0개).

## 8. 롤아웃

1. 파이프라인·사이트 구현. 언어 메뉴는 비공개 플래그(`?i18n=1`) 뒤에 둔다. `/`는 계속 `ko`.
2. 최근 노출분(약 240장 × 4개 언어) 백필, 5개 언어 렌더 검증, 사용자 검토.
3. 공개 전환: `/` 언어 감지 리다이렉트 + 언어 메뉴 노출. 일일 자동 실행에 번역 단계 편입.
4. 전체 2,534장 백필(서브에이전트, 여러 날에 나눠) → 아카이브 라벨 소거 확인.
5. 후속 스펙: 글로벌 결제.

## 9. 범위 밖

- **글로벌 결제:** 해외 사용자 확대로 국내 PG(토스페이먼츠) 단독안 대신 판매대행(MoR, 예:
  Paddle·Lemon Squeezy)을 중심으로 재검토한다. 사업자등록 없이 가입 가능한지는 업체별 확인
  필요. 별도 스펙.
- 풀 밖 언어의 사이트 노출, 사용자 임의 언어 실시간 번역, 언어별 큐레이션(언어권별 다른 기사 선택).
