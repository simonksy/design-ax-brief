# 주간 비즈니스 리포트 설계

**작성일:** 2026-10-02 (2026-10-06 개정 — 매일 브리핑 제외, 주간 리포트만)
**상태:** 승인됨
**선행:** Paddle 구독 결제 (`2026-10-02-paddle-subscription-design.md`) — 구독자 테이블·권한 판정을 그대로 쓴다

## 1. 목적

Pro 구독의 가치를 "더 많이 읽을 수 있다"에서 **"내 일을 대신 해준다"**로 옮긴다.

지금 Pro와 무료의 차이는 분량뿐이다(하루 8장 대 40장, 보관함 열람). 분량만으로는 월 5.99달러를
정당화하기 어렵다. 사이트에 들어와야만 가치가 생긴다는 점도 약하다.

**주간 비즈니스 리포트 하나만 만든다.** 카드 한 장에서는 보이지 않는 흐름을 짚어
가격을 정당화한다.

매일 브리핑은 이번 범위에서 뺀다. 사이트가 이미 매일 발행하므로 같은 내용을 메일로
한 번 더 미는 셈이고, 발송량이 구독자 수 × 30통으로 뛰어 Resend 무료 한도를 구독자
100명에서 넘긴다. 주 1회면 구독자 750명까지 무료 한도 안에 들어온다.

## 2. 무엇이 "리포트"인가

카드가 "무슨 일이 있었나"라면 리포트는 **"그래서 무엇이 바뀌고 있나"**를 말한다.
단순 요약 모음이면 만들 이유가 없다.

주간 리포트는 네 부분으로 고정한다.

**① 이번 주의 변화** (한 문단)
그 주 가장 중요한 움직임 하나를 지목하고 근거 카드 3~5장을 단다.
예: "AI 음악 저작권에서 '학습 데이터 출처 증명'이 처음으로 실제 비용이 됐다."

**② 분야별 신호** (구독자가 고른 섹션마다 2~3줄)
요약이 아니라 "무엇이 움직였고 당신 일에 무슨 의미인가".

**③ 흩어진 점 잇기** (한 문단) — **이 리포트의 핵심**
한 섹션만 보면 안 보이는 교차 패턴. 지식 네트워크가 이미 공유 키워드로 2,452개 노드와
9,501개 연결을 계산해 두므로, 그 주 카드들이 걸쳐 있는 클러스터에서 교차 섹션 묶음을 뽑는다.
예: "이번 주 음악 저작권·EU 규제·출판 세 곳이 동시에 '출처 증명'으로 수렴했다."

**④ 다음에 볼 것** (2~3개)
근거 있는 것만. 계류 중인 법안, 발표 예정 베타. 추측 금지.

## 3. 비용 구조 — 설계의 중심

**구독자 수와 생성 비용을 분리한다.** 1인당 생성하면 구독자가 늘수록 적자가 커진다.

주당 생성량은 **고정 50개 블록**이다(섹션 9개 기준).

| 블록 | 개수 | 산출 |
|---|---|---|
| 분야별 신호 | 9 섹션 × 5 언어 | 45 |
| 이번 주의 변화 + 흩어진 점 잇기 | 5 언어 | 5 |

개인별 메일은 이 블록들을 **조립**해서 보낸다. 구독자가 1명이든 1만 명이든 LLM 호출은 50회다.

## 4. 구성

### 4.1 무료 / Pro 구분

| | 무료 | Pro |
|---|---|---|
| 주간 리포트 | **①번 문단만** | 전체 |

무료에게 ①만 보내는 이유: 가장 좋은 한 문단을 읽고 나머지가 잠겨 있을 때 전환이 일어난다.
아무것도 안 보내면 구독을 떠올릴 계기가 없다.

### 4.2 AI 작성 명시

리포트는 AI가 쓴다. 매주 사람이 쓸 수 없다.

**메일 하단에 반드시 밝힌다**: "이 리포트는 AI가 작성합니다."

사람이 검수하지 않기로 했으므로 "사람이 검수합니다"는 쓰지 않는다. 지키지 않을 약속을
적지 않는다. 숨기는 것보다 정직한 표기가 이 사이트 성격에는 오히려 설득력이 있다.

### 4.3 수신 설정

구독자가 고르는 것:
- 받을 섹션 (기본: 전체 9개)
- 언어 (기본: 현재 사이트 언어)
- 주간 리포트 on/off

설정 화면은 로그인 후 접근하는 단일 페이지. 구독자가 아니어도 주간 리포트 ①번은 받을 수 있으므로
이메일만 등록한 사람도 설정에 들어올 수 있어야 한다.

### 4.4 수신 거부

**모든 메일 하단에 한 번의 클릭으로 끊는 링크를 넣는다.** 로그인을 요구하지 않는다 —
서명된 토큰을 링크에 담아, 누르면 바로 해지된다. 법적 요건이고, 요구하면 스팸 신고로 간다.

## 5. 데이터

```sql
CREATE TABLE IF NOT EXISTS mail_prefs (
  email        TEXT PRIMARY KEY,
  lang         TEXT NOT NULL DEFAULT 'ko',
  sections     TEXT NOT NULL DEFAULT '*',   -- '*' 또는 쉼표로 구분한 섹션 키
  weekly       INTEGER NOT NULL DEFAULT 1,  -- 0/1
  unsub_all    INTEGER NOT NULL DEFAULT 0,  -- 전체 수신 거부
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL
);

/* 같은 메일을 두 번 보내지 않기 위한 발송 기록. 재시도·중복 실행에 안전해야 한다. */
CREATE TABLE IF NOT EXISTS mail_sent (
  id         TEXT PRIMARY KEY,   -- 'weekly:<edition>:<email>' 예) 'weekly:2026-W40:a@b.com'
  sent_at    INTEGER NOT NULL
);
```

주간 리포트 블록은 D1이 아니라 **빌드 산출물**로 둔다 — `reports/<edition>/<lang>.json`.
정적 자산이라 Worker가 바로 읽고, 과거 리포트를 사이트에서 보여주기도 쉽다.

## 6. 흐름

### 6.1 주간 리포트 생성 (주 1회, 파이프라인)

1. 그 주 발행된 카드를 모은다 (`pipeline/archive.json`에서 날짜 범위로).
2. 섹션별로 묶어 **분야별 신호** 블록을 생성한다 (9 × 5 = 45회).
3. 그 주 카드들이 속한 그래프 클러스터에서 **둘 이상의 섹션에 걸친** 묶음을 뽑고,
   가장 큰 것으로 **이번 주의 변화**와 **흩어진 점 잇기**를 생성한다 (5 × 1회, 두 문단 한 번에).
4. `reports/<edition>/<lang>.json`에 쓴다.
5. 사람이 읽어볼 수 있도록 생성 결과를 출력한다 — 검수 절차를 둘 경우의 진입점.

### 6.2 발송 (Cron Trigger)

- 주간 리포트: **매주 월요일 07:00 KST** (기존 발행 크론과 같은 시각대)

발송 전에 `mail_sent`를 확인하고, 보낸 뒤 기록한다. **Cron이 두 번 돌아도 두 번 가지 않는다.**

Resend는 배치 발송을 지원하므로 한 번에 여러 수신자를 보낸다. 실패한 주소는 로그에 남기고
다음 회차에 재시도하지 않는다 — 지난 호를 뒤늦게 보내는 것보다 건너뛰는 게 낫다.

### 6.3 메일 안에서 사이트로

모든 카드 링크는 `/<lang>/?c=<section>:<id>` 형태로, 이미 있는 딥링크를 쓴다.
Pro가 아닌 수신자가 잠긴 카드를 누르면 기존 구독 모달이 뜬다.

## 7. 테스트

- **조립**: 섹션·언어 설정에 따라 올바른 블록만 담기는가
- **멱등성**: 같은 edition을 두 번 발송해도 한 번만 나가는가
- **무료/Pro 구분**: 무료 수신자의 주간 메일에 ②③④가 들어가지 않는가 (유료 콘텐츠 유출)
- **수신 거부**: 토큰 링크 한 번으로 끊기는가, 끊긴 주소에 다음 회차가 안 가는가
- **블록 누락**: 어떤 섹션의 블록 생성이 실패했을 때 그 섹션만 빠지고 메일은 나가는가
- **빈 주**: 그 주 카드가 없으면 메일을 보내지 않는가

## 8. 작업 순서

1. `mail_prefs` / `mail_sent` 스키마 + 설정 읽기·쓰기 API
2. 수신 설정 화면 + 수신 거부 링크 (토큰 서명은 기존 `crypto.js` 재사용)
3. **배관 검증용 최소 발송** — 블록 한 개짜리 더미 리포트를 내 주소로 한 통 보낸다.
   LLM 없이, 조립·발송·수신 거부가 실제로 도는지부터 확인한다.
4. 주간 리포트 블록 생성 (파이프라인, LLM)
5. 주간 리포트 조립 + 발송, 무료/Pro 분기
6. Cron Trigger 등록(월 07:00 KST), 실제 1회 발송 검증

**3번을 4번보다 먼저 한다.** 메일이 실제로 도착하는지부터 확인해야 리포트 품질을 논할 수 있다.

## 9. 결정된 사항 (2026-10-06)

- **발송 시각** — 매주 월요일 07:00 KST.
- **검수** — 사람이 검수하지 않는다. 메일에는 "AI가 작성합니다"만 적는다.
- **범위** — 주간 리포트만. 매일 브리핑은 만들지 않는다.
- **Resend 한도** — 주 1회면 구독자 750명까지 무료 한도(월 3,000통) 안이다.
  그 전에 유료 전환($20/월, 50,000통)을 검토하면 된다. 지금은 제약이 아니다.

## 10. 남은 미결

- **과거 리포트 공개 여부** — 사이트에서 지난 리포트를 보여줄지. 보여준다면 그 자체가
  홍보가 된다. 1차 발송이 안정된 뒤에 정한다.
