# 인스타그램 카드뉴스

사이트 카드의 문법(위 시각 블록, 아래 제목·요약)을 인스타그램 캐러셀로 옮긴 것이다.
사이트는 카드 한 장이 뉴스 한 건이지만, 여기서는 **한 이슈를 여러 장에 쪼갠다** —
스와이프로 읽히므로 한 장이 하나의 microbite만 담아야 한다.

## 돌리는 법

```
python3 social/instagram/render.py social/instagram/<날짜>-<슬러그>
```

포스트 폴더 안의 `cards.json`을 읽어 `out/`에 1080×1350 PNG와, 영상이 있으면
MP4를 굽는다. 헤드리스 크롬과 ffmpeg을 쓴다(둘 다 이 기계에 있다).

`NODE_OPTIONS`가 오염돼 있으면 크롬이 아니라 그 전에 죽는다. `unset NODE_OPTIONS`.

## 새 회차 만들기

1. 폴더를 하나 판다: `social/instagram/2026-10-20-무슨이슈/`
2. 기존 `cards.json`을 복사해 내용만 갈아 끼운다.
3. 돌린다.

`render.py`는 손댈 일이 거의 없다 — 레이아웃만 들어 있다.

## cards.json

`media`와 `video`는 **저장소 루트 기준 경로**다(`pipeline/media/<카드 id>.jpg`).
사본을 두지 않는 이유는 같은 그림이 두 벌이 되면 한쪽만 고쳐지는 날이 오기
때문이다. 다만 `pipeline/media/<id>.*`에는 날짜 네임스페이스가 없어서 같은
슬러그가 재사용되면 덮어쓰인다 — 그래서 **구운 결과물(`out/`)은 커밋한다.**
원본이 바뀌어도 올렸던 것은 남는다.

시각 블록은 `kind`로 고른다. 세 종류가 같은 높이를 쓰므로 넘길 때 글이 같은
자리에서 시작한다.

| `kind` | 쓰는 곳 |
|---|---|
| `cover` / `photo` | 사진. `media` 필요 |
| `stat` | 숫자가 이야기인 대목. `stat_top` / `stat_arrow` / `stat_bottom` |
| `quote` | 인용이 이야기인 대목. `quote` / `quote_by` |

`stat`과 `quote`는 사진이 없는 대목에서도 레이아웃 문법을 지키려고 둔 것이다.

## 글 길이

시각 블록 높이는 본문 길이에 따라 760/660/580으로 자동으로 줄어든다. 처음에는
고정 760이었는데 본문이 긴 카드에서 **푸터가 화면 밖으로 밀려 출처 표기가
사라졌다.** 그래도 넘치면 글을 줄여야 한다 — 글자를 더 줄이는 쪽은 읽기 나빠진다.

## 내용 규칙

- **한 이슈에 집중한다.** 링크 하나일 필요는 없지만, 여러 출처를 교차 대조해
  숫자와 인용을 확인한 뒤 쓴다. 카드 요약만 보고 쓰면 요약의 오차가 그대로 간다 —
  2026-10-13 회차에서는 원문을 받아 보고 나서야 인용의 뒷부분과 "왜 그런지"가
  나왔다.
- **푸터에 출처를 적는다.** 다른 매체의 취재를 옮기는 것이므로 어느 매체인지
  매 장에 남는다.
- 마지막 장은 결론으로 닫는다. 사실 나열로 끝내면 스와이프한 이유가 없다.

## 배포에서 빠져 있다

`social`은 `.assetsignore`에 있다. 사이트가 서빙할 이유가 없고, 올리기 전 원고가
공개되면 곤란하다.
